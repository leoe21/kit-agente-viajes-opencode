CÓMO SE USA ESTE ARCHIVO
------------------------
- Un prompt por cada ladrillo del mapa de 10 pasos. Se pegan en OpenCode UNO
  POR UNO, en orden, siguiendo el ciclo de clase:
      Explico  ->  Pido a OpenCode (pego el prompt)  ->  Revisamos  ->  Probamos
- Cada prompt está entre las líneas  >>> COPIAR DESDE AQUÍ  y  <<< HASTA AQUÍ.
  Se copia solo lo que hay entre esas marcas.
- OpenCode pide permiso antes de crear o cambiar archivos. Se lee lo que propone,
  se aprueba, y recién entonces se pasa al siguiente paso.
- Esta carpeta (el kit) ya trae la SEMILLA: AGENTS.md (el contexto del proyecto)
  y la skill de OpenCode `nueva-skill-viaje`. OpenCode los lee al abrir aquí.
- El proyecto que vaya creando OpenCode (data/, skills/, agent.py, app.py, etc.)
  está en .gitignore: la carpeta se puede reiniciar y rearmar las veces que haga
  falta (ver INSTALACION.md, paso 7).
- Respaldo: si un paso se traba en vivo, el archivo equivalente ya existe en
  C:\Git_Hub_leoe21\agente-viajes y se puede copiar a mano para seguir.

ANTES DE EMPEZAR (ver INSTALACION.md)
-------------------------------------
- Abrir OpenCode EN ESTA CARPETA:  opencode
- La API key de Groq NUNCA se pega en el chat ni en el código. Se configura
  aparte (INSTALACION.md, paso 3): variable de entorno para probar por consola,
  o .streamlit\secrets.toml (ignorado por git) para la app.

Paso 1 del mapa ("La idea") es solo la explicación de arranque: no lleva prompt.
Paso 10 ("Desplegar") tampoco usa OpenCode (se hace en share.streamlit.io).
Los prompts cubren los pasos 2 a 9.

SOBRE LAS DOS CLASES DE "SKILL"
-------------------------------
- Skill del AGENTE  = herramienta de Parcero, un archivo Python en skills/ con
  el patrón TOOL + run (lo que se construye en los pasos 3 y 4).
- Skill de OPENCODE = capacidad que se le da a OpenCode para construir esas
  skills bien. Aquí hay una: `nueva-skill-viaje`. Se invoca escribiendo
  `@nueva-skill-viaje` en el prompt. La usamos como atajo en los pasos 3 y 4.

 PASO 7 · EL CEREBRO  ->  agent.py
===============================================================================
Qué hace: el bucle de "tool use". Idea de clase: esto es lo que convierte un
chat en un AGENTE: el modelo decide qué skill usar, se ejecuta, y el resultado
vuelve al modelo hasta dar la respuesta final.

>>> COPIAR DESDE AQUÍ
Crea agent.py, el cerebro del agente. No debe saber nada de Streamlit (así se
puede probar por consola). Incluye:
- Configuración del proveedor: BASE_URL = "https://api.groq.com/openai/v1" y
  MODELO = "llama-3.3-70b-versatile".
- cargar_sistema(): lee prompts/sistema.md.
- crear_cliente(api_key=None): crea el cliente de OpenAI con base_url = BASE_URL;
  usa la key dada o la variable de entorno GROQ_API_KEY; si falta, lanza un error
  claro. NUNCA escribas una key en el código.
- ejecutar_agente(cliente, historial, modelo=MODELO, max_vueltas=6): corre el
  bucle. En cada vuelta antepone el mensaje de sistema, llama al modelo pasándole
  TOOLS y tool_choice="auto". Si el modelo pide herramientas, ejecuta cada una
  con DISPATCH (capturando errores para que una skill que falle no tumbe el
  agente), devuelve el resultado como mensaje role "tool" y repite; si el modelo
  responde texto, lo devuelve. Devuelve (texto_final, pasos), donde pasos lista
  las skills usadas y sus argumentos. El historial se va modificando para
  conservar la memoria de la conversación.
- Un bloque if __name__ == "__main__" que permita probarlo por consola:
    python agent.py "quiero 4 días de playa y fiesta, presupuesto medio"
Importa TOOLS y DISPATCH desde skills. Coméntalo bien.
<<< HASTA AQUÍ

Revisar: BASE_URL y MODELO correctos; nada de claves en el código; el bucle
tiene tope de vueltas. Probar (con la key ya puesta en el entorno):
